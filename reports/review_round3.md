## R3 预算检查

| 方面 | 检查结果 |
| --- | --- |
| 独立月份与持久化 | `repository.py` 新建 `monthly_budgets`，月份为主键；参数化 upsert 只新增/更新目标月份。清除只删除目标月份预算，没有删除消费流水或重建 expenses 表的逻辑。写入复用现有连接事务与错误包装。 |
| 范围与校验 | `service.py` 的 set/get/clear 均调用 month_bounds 校验月份。保存预算复用 parse_amount，拒绝 0、负数、非有限值、超过两位小数与超过上限金额；数据库再次约束整数分类型和范围。None 表示未设置，与零分明确区分。 |
| 阈值 | `calculate_budget_status()` 验证非负整数支出，拒绝 bool/float；预算必须为有效整数分。先判断大于和等于预算，剩余情况以 `spent * 100 >= budget * 80` 判定接近预算，80% 包含边界，100% 为 exhausted，超出为 over，没有浮点舍入误差。 |
| 极小预算及空月 | 1 分预算下，0 分正常，1 分用完，2 分超支；不存在可表示的整数分落在 80%～100% 区间属于合理结果。空月总支出 0，显示全部剩余额度。 |
| 超支展示 | BudgetStatus 保留负整数剩余额度；界面在超支时先取负转换为正数再调用 format_amount，避免直接格式化负整数产生错误金额。 |
| 提醒依据 | refresh 先取完整月份报告，将该报告的 total_cents 传给 budget_status，预算提醒与当次全月统计一致，没有额外计算与显示舍入。 |
| 切月及写后状态 | 查询月份改变、消费增删改和手动刷新均读取目标月份预算并更新提醒。跨月编辑切到目标月份后刷新；旧月份在重新查看时按数据库重算。预算设置/清除成功后也刷新状态。 |
| 错误恢复 | 预算保存/清除异常时保留未保存输入。读取异常时清除旧预算输入与提醒，显示状态未知，避免把旧月份预算显示成新月份预算。写成功但读失败分支明确区分已提交与刷新失败，沿用 R2 修复原则。 |
| SQL 与数据隔离 | 新预算 SQL 均采用参数占位符，月份/金额不拼接进 SQL。主键 upsert 保持每月仅一份预算，清除不影响其他月。 |
| 文档 | README 说明整数分、阈值含义、独立月份、清除不删流水、刷新清空草稿及只在应用内提醒，和当前代码行为一致。 |

## 需要测试确认的场景

1. 79.99%/80%/99.99%/100%/超支，以及不能整除的预算（例如 3 分、6 分）、1 分预算及空月。
2. 预算首次保存、重复设置、重启后加载、两个月独立、清除目标月预算不影响流水和其他月份。
3. 月份非法、零/负数/超限金额、bool/浮点支出及整数类型边界。
4. 增删改消费跨过阈值、跨月修改、切月和手动刷新后的提示同步；预算读写错误及“写入成功但刷新失败”状态。

## 保留的设计限制

- 刷新、切月和预算设置/清除后的刷新仍清空未保存消费表单；刷新也替换未保存预算输入。README 已明确说明。R1 建议的草稿保护尚未实现，不把它误报为此次修复回归。
- 月消费报告与预算使用独立数据库连接读取，没有承诺多进程并发时的同一事务快照；当前适用个人单实例规模。若后续引入同时编辑，需定义并发一致性要求。
- 提醒在已打开应用中刷新时更新，没有后台或系统通知；这与本轮功能及文档一致。
- 本轮不执行数据库迁移运行验证，也不宣称新建预算表已在所有已有数据库结构上验证。应由测试覆盖正常 R1 数据库升级后保留旧流水。
