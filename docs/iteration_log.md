新作业第1轮（初版）。仅在 E:\Code\sofwar_engineing\CampusExpenseTracker 中工作，绝不改旧 PyQtWeatherApp。选题：个人校园消费记账 GUI。用 Python3.10+、PyQt6（PyQt6==6.8.1，PyQt6-Qt6==6.8.2，沿用已验证组合）、标准库 sqlite3 实现中文桌面应用：记录消费日期、分类（餐饮/交通/学习/购物/娱乐/其他）、金额、备注；新增/选择记录编辑/删除确认；按月份查看流水、月总支出及分类统计；SQLite 持久化，默认数据库在项目 data 目录，入口可用 --db 指定路径，后续方便注入临时数据库测试。金额用 Decimal 严格解析为整数分，不用浮点累计；合理校验金额/date/category/note、参数化 SQL、错误可见而非崩溃。月份变更时编辑表单状态应清晰。模块化 repository/service/ui，提供 README、requirements 和 gitignore（忽略venv/数据库/缓存/tmp）。本轮不实现预算提醒、分类筛选或 CSV 导出，这些留作真实后续功能迭代；初版本身要完整稳健，绝不故意留 bug。只写业务代码，不写或执行测试，可以语法自检。工作目录外部默认 cwd 仍是旧项目，工具必须指定新项目 workdir/绝对路径。不要创建子Agent。完成后汇报文件、接口与已知限制，等待下一轮。

## 第2轮：具体缺陷修复

**发现的问题或目标：** 取消选择后旧金额和备注残留在新增表单；写入完成后若读取失败，错误状态被普通成功文案覆盖。

**实际开发提示词（主控 → CodeWriter）：**

```text
新作业第2轮：只修改 E:\Code\sofwar_engineing\CampusExpenseTracker 的业务源码与 README。针对 R1 审查/测试发现的两个具体状态问题修复：
1. 用户选中记录再取消选中时，界面进入新增模式但仍保留旧记录金额/备注，可导致误新增重复账目。改为取消选择后回到干净新增表单（日期遵从当前查看月份默认值），同时避免 clearSelection 与 itemSelectionChanged 的递归；选中记录、刷新、取消编辑和跨月保存仍正常。
2. save_record/delete_record 完成数据库写入后调用 refresh；若读取失败，refresh 已显示错误但外层仍覆盖成“已新增/修改/删除”。让 refresh 明确返回成功状态，后续仅在刷新成功时显示普通成功提示；读取失败时明确“写入已完成，但刷新失败”，避免诱导用户重复保存。保留读取错误信息，不要吞异常或伪报成功。
请参考 TestEngineer 已保存的 R1 回归证据 reports/round1_regressions.log（4/4 失败），不改测试或报告，不运行测试，仅语法自检。已有行为兼容；其余预算/筛选/CSV 留到后续迭代。本轮不引入未保存确认等额外功能，README 准确描述刷新清空表单的行为。完成给出实际修改摘要。
```

**AI 实际改动：** 统一重置新增表单并阻断选择信号递归；refresh 返回成功状态；写入完成但刷新失败时明确说明两种结果并保留错误，避免误重复提交。

**验证结果：** 同一批 4 条回归全部通过（0.70 秒）；完整测试 96/96 通过（2.59 秒）。原始失败证据未覆盖。

## 第3轮：月预算与提醒

**发现的问题或目标：** 只有消费统计不足以帮助控制生活费，需要分月预算，并能解释剩余或超支。

**实际开发提示词（主控 → CodeWriter）：**

```text
新作业第3轮：在 E:\Code\sofwar_engineing\CampusExpenseTracker 的 R2 基础上加入按月预算与提醒。各月预算独立存于 SQLite 新表，重复设置更新同月预算，建表不得覆盖旧流水；未设置预算用 None/明确状态，不能混同0。预算金额复用严格整数分校验，可设置0.01～999999.99元，并提供清除当前月预算操作。服务层提供独立可测的设置/读取/清除及预算状态；界面显示本月预算、全月总支出、剩余或超支，达到80%提示接近、达到100%提示已用完、超过100%显示超支，阈值比较用整数，预算提醒为应用内提示，不声称后台通知。新增/编辑/删除及切换月份时更新提醒，空月/未设置/清除预算状态清楚，数据库错误可见且不把预算写入成功后的刷新错误伪报成功。README更新使用与提醒说明。只改业务源码和README，勿改测试/reports/docs/Git，不运行测试，可语法自检；保留R2修复，不做筛选或CSV。完成报告实际改动和新增接口。
```

**AI 实际改动：** 新增独立月预算表、设置/更新/清除预算、80%/100%/超支三种提醒；整数比较阈值，预算随月份独立保存；旧流水保留。

**验证结果：** 全量 144/144 通过（9.41 秒）。首次曾有测试预期写错：79.99/99.99 低于 80%，应为 normal；修正测试而非业务，并保留首次 143 通过、1 失败的证据。

## 第4轮：分类筛选与 CSV 导出

**发现的问题或目标：** 需要只查看某类消费并导出结果，同时确保预算不会被筛选结果误导，导出不会损坏账本。

**实际开发提示词（主控 → CodeWriter）：**

```text
新作业第4轮：仅在 E:\Code\sofwar_engineing\CampusExpenseTracker 增加分类筛选与 CSV 导出。以 R3 为基础，新增独立的“全部分类/六类”筛选控件（不要复用录入分类），筛选当前月份流水，显示当前筛选条数/小计；月总支出和预算提醒始终按全月计算，避免筛选后假装预算变多。筛选变更清空编辑身份与旧表单，保存/跨月/刷新行为清晰。服务层提供可独立测试的过滤和导出接口。导出用户指定路径的当前月份+当前分类流水，中文表头，金额固定两位，UTF-8 BOM，csv.writer处理逗号/引号/换行。导出备注要防表格公式注入（包括前置空白后=,+,-,@，加单引号等可识别的安全处理），不能因此修改数据库原备注。取消对话框不落盘；空结果可导出表头并说明0条。导出须拒绝覆盖当前数据库，即使数据库扩展名是.csv；建议要求.csv后缀、用目标同目录临时文件+原子替换，避免写失败破坏已有文件，并保证临时文件清理。现有文件覆盖需要GUI确认，文件/权限/编码错误转可见业务错误，失败不能报成功。README更新筛选/导出范围与CSV安全处理。保留已有CRUD、预算和R2修复。不要修改 tests/reports/docs/Git，不运行测试，仅语法自检。无需后台任务或额外图表；保持默认窗口在常见屏幕可见。完成说明接口及限制。
```

**AI 实际改动：** 增加独立分类筛选和筛选小计；预算和月总额仍按全月计算。增加中文 CSV、两位小数、BOM、特殊字符转义、公式防护、数据库目标保护及写入失败处理。

**验证结果：** 最终完整测试 177/177 通过，无失败、错误、跳过；详见 reports/test_report.md、pytest_output.txt 和 junit.xml。另生成实际 Qt 预览图用于布局检查。

## 我们如何确认结果正确

- 采用真实临时 SQLite 文件，增删改查后关闭重开，确认持久化；所有测试不触碰正式 data 目录。
- 金额用明确样例交叉核对：12.30+2.00+0.10+0.20=14.60 元；0.10+0.20 精确为 0.30 元。覆盖 0、负数、三位小数、非数字、上下限等边界。
- 日期使用闭开月区间，验证闰日、12 月跨年及 2100-12 上界。
- 预算用分为单位的整数乘法比较，分别检查低于80%、刚好80%、刚好100%和超过100%，并验证各月互不干扰。
- GUI 测试实际创建 QApplication/窗口，驱动选择、保存、删除确认/取消、切月和故障恢复；不是仅检查函数存在。
- CSV 检查中文 BOM、两位金额、筛选范围、逗号/引号/换行、公式前缀防护和失败时既有文件/数据库保护。
- 初版缺陷的失败日志与修复后的通过日志分别保存；测试预期写错也如实保留，不将它算成产品缺陷。

实际 Qt 预览见 `reports/app_preview.png`。它来自合成样例和 offscreen 渲染，不包含用户真实账目。首次渲染出现文字方框，主控通过图像检查发现，TestEngineer 在预览脚本显式加载本机微软雅黑字体后重做；主控复核中文、金额、预算、列表、表单与按钮均可读，未见明显裁切或重叠。该修复只修改预览脚本，不修改业务。布局检查不等于已进行原生 Windows 人工操作、多显示器/DPI 或性能验收。
